# MVC Generator

## Purpose

Generate a complete set of backend CRUD pages with one command: entity, migration, seeder, controller, grid/list view, edit view, and route. Use it to quickly create backend pages or reproduce bugs in generated pages. Generate a disposable copy, test it, and then delete it.

## When to use

- Creating a new backend CRUD module.
- Reproducing a bug in an autogenerated list or edit page. Generate a copy with a different name, test it, and delete it afterward.

## Recommended workflow and commands

For the complete workflow to create an entity, migration, field definitions, and module—including command options, generated file structure, and handling existing files—see the official [Code Generation](https://windwalker.io/documentation/unicorn/mvc-crud/code-generation.md) documentation.

The key command in this skill is:

```shell
php windwalker g unicorn:mvc-admin <Stage>/<Name>
```

- `<Stage>` is usually `Admin` or `Front`; backend modules should generally go under `Admin/` with appropriate access controls.
- `<Name>` is a singular PascalCase name, such as `Admin/Product`.
- Before generating, if you are unsure about an option or behavior, consult the official documentation (see below); do not guess.

To generate a frontend screen or a simple page without editing functionality, use:

```shell
php windwalker g unicorn:mvc-simple <Stage>/<Name>
```

## Consult the official documentation first

Before generating, or whenever options or behavior are unclear, consult the official Windwalker documentation; do not guess. Use either of these sources:

- MCP tool `windwalker-docs-search`: make a natural-language query, such as `generator --pkg option`.
- `https://windwalker.io/llms.txt`: an index of documentation pages (each page has a `.md` URL); fetch the relevant page.

Only read the generator source code (`vendor/windwalker/core/src/Core/Generator/`, `vendor/windwalker/unicorn/src/Generator/`) if the documentation cannot answer the question.

## Known behavior

- The generator does not run migrations or seeders. Before running `mig:go`, confirm that you are using a development database.
- Generated `.ts` and `.scss` files must be compiled with `yarn build` (or `yarn dev`), or their interactive features will not work. See the official documentation for search fields and follow-up steps.
- The backend sidebar menu is not generated automatically. Add an item manually to `resources/menu/admin/sidemenu.menu.php`, following an existing item:
  ```php
  $menu->link($lang('unicorn.title.grid', title: $lang('luna.<entity>.title')))
      ->to($nav->to('<snake>_list'))
  ```

## Debugging shortcut

For simple bugs, skip `g entity` and the migration and run `unicorn:mvc-admin Admin/<Name>` directly. The generated entity has only empty properties; if the page needs fields, define the table first and run `build:entity`.

## Templates

To change generated content, edit the templates under `vendor/windwalker/unicorn/views/code/`. Do not edit generated files directly to fix the generator.

- `controller/`: controller class
- `model/entity/` and `model/repo/`: entity and repository
- `route-admin/` and `route-simple/`: route files (`routes/<kebab>.route.php`)
- `view/grid/`: list page: grid form, list view, `assets/` (scss/ts), `views/` (list, modal, toolbar blade)
- `view/edit/`: edit page: edit form, edit view, `assets/`, `views/` (edit blade, toolbar blade)
- `view/list/` and `view/item/`: alternative list and item page templates
- `workflow/`: workflow class

Filenames are templates too, using `{% pascal($name) %}` and `{% kebab($name) %}` placeholders. Template files use the `.tpl` extension.

Vendor files are overwritten by `composer install` / `update`. To preserve changes, copy them into the project or record them in dedicated notes before updating dependencies.

## Debugging workflow (disposable copy)

1. Generate with a different name, such as `Admin/DebugTest<Name>`.
2. If the page needs a table, define and run a migration as recommended, then run `php windwalker mig:go` and reproduce the bug.
3. When finished, delete all files created by the generator:
   - `src/Entity/<Name>.php`, `src/Repository/<Name>Repository.php`
   - `resources/migrations/*_<Name>Init.php`
   - `resources/seeders/<kebab-name>.seeder.php`
   - `src/Module/Admin/<Name>/` (the entire directory)
   - `routes/admin/<kebab-name>.route.php`
   - Any menu item added to `resources/menu/admin/sidemenu.menu.php`
   - If a migration was run, roll it back and delete the table.
4. Run `git status` to confirm no generated files remain.

## Verification

- After cleanup, `git status` shows only the expected files.
- Before cleanup, the generated list and edit pages load correctly in a browser.
