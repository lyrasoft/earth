# i18n / Multilingual Guidance

Use when adding or modifying translatable text in `windwalker/unicorn`.

- Public documentation: <https://windwalker.io/documentation/components/language/index.md>
- Before adding, renaming, or reusing a key, read the naming guidance in the project's instructions and docs.

## Available mechanisms

- Language files: `resources/languages/<locale>/unicorn.ini`; locales are `en-US` (fallback) and `zh-TW`.
- Lookup order: current locale → fallback → parent. If no translation is found, the key itself is returned; debug mode displays `??key??`.
- Installation: `UnicornPackage` copies files tagged `lang` into the host's `resources/languages`; the host can override them.

## Keys

- Start with `app.`, use lowercase dot-separated segments, and group by domain (such as `app.field.*`, `app.message.*`, and `app.title.*`).
- Do not use `_`, `-`, or camelCase to distinguish keys; these are normalized to the same key.
- Do not build keys from user input. Dynamic suffixes must come from a closed set, and each value must have a corresponding key.

## Language files (`.ini`)

- Format: `key="value"`, UTF-8, with values enclosed in double quotes. Escape a literal `"` in a value as `\"`; escape a literal `%` in positional format strings as `%%`.
- Placeholders: use either named placeholders, such as `:name` (`trans('k', name: $v)`), or positional placeholders, such as `%s` / `%d`, but not both in one string. Placeholders must match across locales.
- Values may contain HTML, but only intentionally.
- Deleting or renaming a key is a breaking change; search for usages first.

## Backend (PHP)

- In container-managed classes, use `TranslatorTrait` (`trans()` and `choice()`) or inject `LangService`; do not use `new LangService` / `new Language`.
- Pass named arguments by name (`trans('k', name: $v)`); an array as the second argument is invalid.
- Use `choice()` for plurals, `raw()` for text that should not be translated, and `LangService::has()` to check optional keys.
- Labels generated by `FormFieldsBuilder` follow the `$this->trans('<key>')` contract; preserve it.

## Sending translations to the frontend (TypeScript / Vue)

- PHP export: `$unicornScript->translate('key')`, `translate(['a.b'])`, or `translate('prefix.*')`.
- TS access: `__('key', max)` (positional) or `__('key', { title })` (named), defined in `assets/src/service/lang.ts`.
- Every key used by `__()` must be exported by the PHP path that loads that module: globally in `UnicornScript::main()`, or for a module in its corresponding script class (such as `FormScript`).
- When adding frontend text, update both locale INI files and add both `translate()` and `__()` calls.
- Prefer a wildcard for a whole group of keys. Do not call `__()` with a key assembled at runtime unless the entire group has already been exported.
- Do not hardcode user-visible text or put secrets or unescaped HTML in language strings.
- `assets/dist/` contains build artifacts; do not edit it manually.

## Verification

- Compare the sets of keys in the locale files.
- Search for usages: `grep -r "app.some.key" src views assets/src`.
- Set `LANG_DEBUG=1` and check whether pages display `??key??` (a missing PHP key or a JS key not exported with `translate()`).
- Compare all locale keys again to ensure they strictly follow the naming rules.
